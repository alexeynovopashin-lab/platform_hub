# platform_hub — согласование проектов платформы

Создан 08.10.2026 по слову Алексея: «Надо создать единый документ согласования. Отдельный гит оркестратора платформы, ранее я предполагал, что EventOS будет таким оркестратором, но это отдельный проект, который имеет свои задачи». Решения при создании: ведёт хаб отдельный чат «Платформа»; чаты узнают о новом из файлов, плюс скрипт `hub.sh`; репозиторий публикуется на GitHub (публичный).

Зачем: проекты задают друг другу вопросы и договариваются об общих интерфейсах здесь, а не через Алексея. Алексей получает только то, что решает сам (`FOR_ALEXEY.md`).

## Файлы

- `QUEUE/<проект>.md` — входящие вопросы к проекту. Отвечает только этот проект.
- `CONTRACTS/` — общие интерфейсы между проектами, один файл на интерфейс.
- `DECISIONS.md` — решения Алексея уровня платформы, дословно, с датой. Только дописывать.
- `CONFLICTS.md` — найденные противоречия между проектами и ошибки в чужих пересказах.
- `FOR_ALEXEY.md` — только то, что решает Алексей: 2–3 варианта простыми словами, плюс, минус, совет.
- `STATUS.md` — одна строка на проект: что в работе, что блокирует.
- `sources/` — исходные файлы, которых нет в репозиториях проектов (принесённые Алексеем). Не правятся.
- `hub.sh` — что открыто для проекта, новый вопрос, сводка.

## Правила для чатов проектов

1. **В начале сессии:** `~/Documents/workspace/10_projects/platform_hub/hub.sh <проект>` (`lightplan`, `eventos`, `bronios`, `site`). Когда Алексей пишет «проверь хаб» — то же самое. Чат без доступа к Mac (облачный проект claude.ai) читает хаб на GitHub: https://github.com/alexeynovopashin-lab/platform_hub (файлы напрямую: `https://raw.githubusercontent.com/alexeynovopashin-lab/platform_hub/main/<файл>`); пишет в хаб через Алексея или чат на Mac.
2. **Вопрос другому проекту:** `hub.sh new <от> <кому> "заголовок"` создаёт запись с номером в `QUEUE/<кому>.md`; ниже дописать текст вопроса и строку «Что меняет».
3. **Ответ:** только в своей очереди, под вопросом: «Ответ (<проект>, дата)», затем сменить статус в заголовке на `отвечен`. Закрывает спросивший (`закрыт`), когда принял ответ.
4. **Факты** — со ссылкой `<метка>:<путь>:<строка>`. Не проверено — так и написать.
5. **Решения Алексея** — дословно и с датой; свой вывод помечать «вывод, не слова Алексея». Не выдавать техническое решение проекта за решение Алексея. Расходятся два решения Алексея — действует более позднее (по его словам 08.10 «это свежие решения, они самые актуальные», `DECISIONS.md`).
6. **Хаб ссылается, а не копирует.** Документ живёт в своём проекте; здесь — ссылка и короткая суть.
7. **Секретов нет** (ключи, пароли, токены, номера клиентов): репозиторий публичный.
8. **Git:** файлы добавлять по имени; `git pull --ff-only` перед коммитом; файлы-журналы только дописывать; force push нельзя.
9. **Ничего не удалять** — закрытое помечается статусом.

## Формат вопроса

```
### Q-001 · от: bronios · кому: lightplan · 2026-10-08 · статус: открыт
Заголовок одной строкой.
Текст вопроса.
**Что меняет:** для студии / фотографа / клиента, простыми словами.
```
Статусы: `открыт` → `отвечен` → `закрыт`; `ждёт Алексея` — если ответ упирается в его решение (тогда же запись в `FOR_ALEXEY.md`).

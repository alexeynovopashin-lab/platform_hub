# Договор: канал «фотограф ↔ студия»

**Участники:** Light Plan (фотограф), BroniOS (студия). Ядро — когда появится сервер `/v1/` (этапы по `platform_hub:docs/PLATFORM_ARCHITECTURE.md` §6). **Статус:** работает в старом виде; переезд — Q-014.

## Как сейчас (факты на 08.10)
- Сервер: воркер BroniOS в Cloudflare, новое имя `broni-auth`, старое `tomson-auth` (на старое ходит веб-бета Light Plan; не удалять, пока «Связать с бронью» в бете нужна — решение Алексея 08.10, A-001).
- Запросы: `/studio`, `/booking/match` (дата + «ЧЧ:ММ», ночные брони не находятся), `/rent/extend` (веб-бета, `minutes: 60`), `/rent/status` (опрос).
- Light Plan Swift: есть только `/booking/match` (`light_plan:native/Packages/LightPlanData/Sources/LightPlanData/Studio/BookingMatch.swift`); продления, «Позвать администратора», сканера QR нет.
- Доступ: общий гостевой ключ `X-Studio-Key`, лимит по IP (вопрос Q-015).

## Решено Алексеем (08.10, `DECISIONS.md`)
Продление «полчаса» / «час»; «Позвать администратора» — два значка (телефон, человечек); перенос брони только согласованно, у фотографа — временное уведомление и пуш; QR в зале — адрес зала, сервер по ID фотографа находит текущую бронь, где он участник; вход по номеру телефона — запасной путь (A-003). «Человечек» до пушей: ответ виден, пока открыта карточка (A-002). Заявки на зал из Light Plan нет, только связь с бронью (A-005).
